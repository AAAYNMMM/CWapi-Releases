**Turn ChatGPT Web into a local coding agent and an OpenAI-compatible AI provider, while keeping your projects and tools on your Windows PC.**

CWapi 2.0 provides two isolated bridges:

- **Coding** lets ChatGPT Web read, edit, build, test, and operate a local Git workspace through MCP.
- **Agent** exposes a localhost OpenAI-compatible API so compatible local software can send model requests to Web GPT through an Agent MCP bridge.

Current release: **`2.0.2`**.

## What is CWapi?

CWapi is a portable Windows desktop bridge. It does not run an AI model itself. Web GPT remains the reasoning agent; CWapi provides local execution, durable repository state, request transport, and a local provider surface.

### Coding

```text
ChatGPT Web
    ↓
CWapi Coding MCP
    ↓
Local durable Git workspace
    ↓
Build / Test / Git / Development Tools
```

The Coding tool catalog is deliberately small:

```text
coding_open
coding_exec
coding_status
coding_close
```

Web GPT is the **only reasoning agent** in this chain. The bundled official Codex runtime is used only as a model-free `command/exec` toolhost and Windows sandbox. CWapi does **not** create a Codex thread or turn, does not hand the task to Codex Agent, and does not require a Codex account/login for Coding.

### Agent

```text
Cline / Roo Code / other OpenAI-compatible software
    ↓
CWapi localhost /v1
    ↓
Agent broker
    ↓
CWapi Agent MCP
    ↓
ChatGPT Web
```

The local provider exposes:

```text
Base URL: http://127.0.0.1:<agent-port>/v1
Model:    cwapi-web-gpt
API key:  generated by CWapi and shown by the GUI
```

Implemented endpoints:

```text
GET  /v1/models
POST /v1/chat/completions
```

Software such as Cline or Roo Code **may** work when configured for a custom OpenAI-compatible provider. Compatibility depends on the client's provider behavior and request features, so CWapi does not claim universal support for every version or plugin.

## Why CWapi?

- Use Web GPT reasoning against a real local Git project.
- Read/search/edit source and execute exact commands without routing the coding task to a second AI agent.
- Build and test in the same durable workspace across ChatGPT conversations.
- Keep normal Coding work in `SAFE`, then switch to `FULL` only for explicitly authorized operations that need `.git` metadata writes or broader host access.
- Give OpenAI-compatible local software a localhost model endpoint backed by Web GPT.
- Keep Coding and Agent independent: separate MCP tokens, tool catalogs, Tunnel configuration, and runtime paths.
- Keep file and image transfer disabled on both MCP surfaces; inspect repository text through bounded `coding_exec` commands.

## Core capabilities

### Coding capabilities

- Open or resume a GitHub repository by URL and branch ref.
- Optional full-commit `expected_commit` baseline guard.
- Durable workspace under `CWapi-data/workspaces/<repository-hash>/repo`.
- Read and search source through exact commands.
- Modify project files in the managed workspace.
- Run compilers, test runners, scripts, local servers, and Git commands.
- Inspect HEAD, tracking HEAD, dirty state, and divergence with `coding_status`.
- Resume the same active repository from a new ChatGPT conversation with compatible `coding_open(..., resume=true)`.
- Keep source and other inspectable text in the command path; Coding exposes no file or image transfer tool.

### Agent capabilities

- Local OpenAI-compatible `/v1` provider bound to `127.0.0.1`.
- Chat Completions request/response and streaming support.
- Function/tool-call responses returned to the local client for that client to execute.
- Multiple independent requests correlated by exact `request_id`.
- Bounded queue and request timeout.
- Structured exchange activity with monotonic revision, queue counts, idle tracking, wait duration, and next-action guidance.
- Terminal responses are acknowledged as `state=responses`; `no_request` means only that a real bounded wait expired without a new OpenAI request.
- Native JSON tool arguments and JSON content are canonicalized to OpenAI-compatible strings.
- Text and tool JSON only; top-level attachments and non-text message content are rejected before broker admission.
- Independent Agent MCP bridge and independent Secure MCP Tunnel configuration.

## 5-minute quick start

1. Download [`CWapi-v2.0.2.zip`](https://github.com/AAAYNMMM/chatgpt-work-api-Releases/releases/download/v2.0.2/CWapi-v2.0.2.zip).
2. Fully extract it to a user-writable directory and run `CWapi.exe`.
3. For **Coding**, create an OpenAI Secure MCP Tunnel, obtain its Tunnel ID and Runtime API key, then enter them in the Coding Tunnel panel.
4. In ChatGPT, use a workspace/plan that supports the MCP capabilities you need, enable the applicable Developer Mode/custom-app flow, and connect the matching Tunnel. ChatGPT cannot directly connect to CWapi's `127.0.0.1` MCP URL.
5. Confirm the Coding tools appear, then try a harmless repository task with `coding_open` followed by `coding_status` or a read-only `coding_exec`.
6. For **Agent**, configure a second independent Secure MCP Tunnel in the Agent Tunnel panel and connect it as a separate ChatGPT MCP app.
7. Open the Agent bridge in ChatGPT with `agent_open` and keep `agent_exchange` running for the continuous task.
8. Configure your local OpenAI-compatible software with the Base URL, model, and Agent API key shown above.

For the full setup, including what Tunnel ID and Runtime API key mean, use [Getting Started](docs/GETTING_STARTED.md).

## SAFE and FULL

`SAFE` is intended for ordinary source inspection, edits, builds, and tests. It uses the Codex sandbox's workspace-write profile and protects `.git` metadata.

`FULL` is for operations the user has explicitly authorized that require Git metadata writes or broader host access, such as local commit/push workflows. It applies to the next `coding_exec`; a command already running keeps the profile it started with. Permanent execution policy still applies.

## Durable workspaces

Closing a Coding session does **not** delete its workspace. The workspace lives beside the portable installation under `CWapi-data` and can be resumed later.

A new non-resume open refuses tracked dirty state, local commits, or divergence rather than silently overwriting them. `resume=true` explicitly continues a compatible existing workspace/session.

If you move the **entire** extracted CWapi directory, its adjacent `CWapi-data` moves with it. If you move only the clean program/runtime files, the new location gets a fresh data root.

## Files and images

CWapi 2.0.2 does not transfer files or images through Coding or Agent MCP. Source, Markdown, JSON, logs, and other inspectable repository text are read with bounded `coding_exec` commands.

Agent accepts text and tool JSON only. Top-level `attachments` is rejected with `AGENT_FILE_ATTACHMENTS_UNSUPPORTED`; non-text message content such as `image_url` is rejected with `AGENT_MEDIA_INPUT_UNSUPPORTED`.

Uploading a file into a ChatGPT conversation does not automatically write that file into a Coding workspace or Agent client.

## Typical use cases

- Continue a real repository task across multiple ChatGPT conversations without recreating the workspace each time.
- Let Web GPT inspect, edit, build, and test a local Git project while keeping reasoning in ChatGPT Web.
- Use an OpenAI-compatible local client as the interface while Web GPT provides the model-side response through Agent.
- Keep Coding and Agent isolated so a repository workflow and a local provider workflow can run independently.
- Work with private Git repositories using the Windows user's existing Git/GitHub credentials.

## Security and privacy

CWapi binds its local MCP and Agent Provider to loopback. Secure MCP Tunnel provides outbound private connectivity for supported OpenAI products without requiring CWapi to expose a public inbound server.

Local secrets are split deliberately:

- Coding and Agent MCP bearer tokens: `CWapi-data/config/cwapi.json`.
- Agent Provider API key: `CWapi-data/config/cwapi.json`.
- Coding/Agent Tunnel IDs: `CWapi-data/config/cwapi.json`.
- Coding and Agent Tunnel Runtime API keys: separate entries in Windows Credential Manager.

CWapi does not maintain a persistent conversation transcript store or full command-output history. Normal observability records bounded metadata/errors rather than full prompts, answers, tool schemas, or tool results.

Read [Security](docs/SECURITY.md) for the detailed boundary.
