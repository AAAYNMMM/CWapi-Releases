# Coding

Description: 用于代码开发、修改、重构和项目实现。

## Rules

- 先读取并遵守项目自己的开发规则、接口约束和相关测试，再修改。
- 先理解相关代码和调用关系，优先搜索相关符号/范围，不无目的地读取整个仓库或超大文件。
- 只做完成当前任务所需的最小改动，避免顺手重构无关区域。
- 长任务按可验证的小步骤推进，一个执行步骤尽量只承担一个明确目的，避免把读取、修改、测试和 Git 操作串成巨型命令。
- 长文本或复杂修改优先使用更稳定的文件编辑/短脚本方式，避免在多层 shell/PowerShell/JSON 转义里嵌入整份大文件。
- 修改后先做针对性验证，再根据风险扩大测试范围。
- 不重复读取没有变化的文件，也不为了减少工具次数重复或堆叠无关操作。
